================================================================================
          POLÍTICA DE HARDENING DE SISTEMAS OPERATIVOS
================================================================================
ID: SEC-HARD-701 | Versión: 1.0 | Clasificación: CONFIDENCIAL
--------------------------------------------------------------------------------

1. OBJETIVO
--------------------------------------------------------------------------------
Establecer un estándar de configuración segura para los sistemas operativos que 
soportan la plataforma Electronics-eCommerce, eliminando servicios innecesarios 
y reduciendo la superficie de ataque mediante el endurecimiento (Hardening).

2. ALCANCE
--------------------------------------------------------------------------------
Aplica a todos los servidores (Físicos, Virtuales o Contenedores) que ejecutan 
servicios de Base de Datos, API y Front-end.

3. ESTÁNDAR GENERAL DE ENDURECIMIENTO (LINUX/UBUNTU)
--------------------------------------------------------------------------------
Se adoptan los benchmarks del Center for Internet Security (CIS) Nivel 1.

A. GESTIÓN DE SERVICIOS Y PUERTOS:
   - Desactivar servicios no críticos (ej: avahi-daemon, cups, rpcbind).
   - Eliminar compiladores (gcc) y herramientas de depuración en producción.
   - Configuración de Firewall Local (UFW/iptables) según el Doc 1.2.

B. BASTIONADO DE ACCESO (SSH):
   - Deshabilitar el acceso directo como usuario 'root'.
   - Cambiar el puerto por defecto del 22 a un puerto no estándar (ej: 2222).
   - Forzar el uso exclusivo de llaves SSH (RSA 4096 bits) eliminando passwords.
   - Establecer un tiempo de inactividad (ClientAliveInterval) de 300 segundos.

C. SEGURIDAD DEL SISTEMA DE ARCHIVOS:
   - Particionamiento separado para /var, /tmp y /home.
   - Montaje de /tmp con opciones 'noexec', 'nosuid' y 'nodev'.

4. ACTUALIZACIONES Y PARCHES (PATCH MANAGEMENT)
--------------------------------------------------------------------------------
- Activación de 'Unattended-Upgrades' para parches de seguridad críticos.
- Ciclo de reinicio mensual programado para la aplicación de parches de Kernel.

5. AUDITORÍA Y MONITOREO LOCAL
--------------------------------------------------------------------------------
- Instalación de `auditd` para registrar cambios en archivos del sistema y 
  llamadas al sistema sospechosas.
- Sincronización horaria obligatoria mediante NTP (Stratum 1 o 2).
