          ESTÁNDAR DE CONFIGURACIÓN DE REGISTROS (LOGGING)
================================================================================
ID: SEC-LOG-401 | Versión: 1.0 | Clasificación: CONFIDENCIAL
--------------------------------------------------------------------------------

1. INTRODUCCIÓN
--------------------------------------------------------------------------------
Este documento detalla la implementación técnica del sistema de registro de 
eventos para la plataforma "Electronics-eCommerce". La trazabilidad es un 
componente crítico para la detección de anomalías y la respuesta ante incidentes, 
cumpliendo con los lineamientos de PCI-DSS.

2. ARQUITECTURA DEL SISTEMA DE LOGS
--------------------------------------------------------------------------------
La aplicación utiliza un motor de logging basado en el middleware `morgan` y 
flujos de escritura de archivos (`fs.createWriteStream`) para asegurar la 
persistencia de los datos en el directorio `/server/logs/`.

COMPONENTES CLAVE:
- Morgan: Generación de logs de acceso y errores HTTP.
- Custom Security Logger: Identificación de patrones de ataque en tiempo real.
- NanoID: Generación de Identificadores de Petición (Request ID) para correlación.

3. ESTRUCTURA Y ARCHIVOS DE REGISTRO
--------------------------------------------------------------------------------

A. REGISTRO DE ACCESO (access.log)
   Almacena todas las peticiones HTTP exitosas (2xx, 3xx).
   Formato: `:remote-addr - :remote-user [:date] ":method :url" :status reqId=:reqId`

B. REGISTRO DE ERRORES (error.log)
   Captura exclusivamente peticiones con códigos de estado 4xx y 5xx.
   Propósito: Identificar fallos en la lógica de negocio o intentos de acceso 
   a recursos inexistentes.

C. REGISTRO DE SEGURIDAD (security.log)
   Archivo crítico en formato JSON que registra eventos sospechosos basados en 
   expresiones regulares (Regex).
   Patrones monitoreados:
   - `/script.*alert/i` (XSS)
   - `/union.*select/i` (SQL Injection)
   - `/drop.*table/i` (Destrucción de BD)

4. TRAZABILIDAD Y CORRELACIÓN
--------------------------------------------------------------------------------
Cada petición entrante es etiquetada mediante el middleware `addRequestId`. 
Este ID se propaga en:
- El header de respuesta `X-Request-ID`.
- Todos los archivos de log asociados a esa transacción.
- La respuesta JSON enviada al cliente en caso de error.

5. ESPECIFICACIONES DE INTEGRIDAD
--------------------------------------------------------------------------------
- Permisos de Archivo: Solo el usuario que ejecuta el servicio Node.js tiene 
  permisos de escritura sobre la carpeta `/logs/`.
- Inmutabilidad: Los logs se escriben en modo 'append' para evitar la 
  sobrescritura de eventos históricos.
