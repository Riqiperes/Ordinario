1. PROPÓSITO
--------------------------------------------------------------------------------
Definir los pasos técnicos y operativos que deben seguirse durante el desarrollo 
de nuevas funcionalidades o correcciones para asegurar la calidad y seguridad 
de la plataforma.

2. PASOS DEL PROCEDIMIENTO
--------------------------------------------------------------------------------

PASO 1: CREACIÓN DE TICKET/HISTORIA
- Debe incluir criterios de aceptación de seguridad (ej: "El campo X debe ser 
  sanitizado contra XSS").

PASO 2: DESARROLLO EN RAMA DE CARACTERÍSTICA (FEATURE BRANCH)
- El desarrollador utiliza entornos locales aislados con bases de datos de 
  prueba (nunca datos reales de clientes).

PASO 3: ANÁLISIS AUTOMATIZADO
- Al realizar el 'commit', se activan 'hooks' de Git para buscar secretos y 
  errores sintácticos de seguridad.

PASO 4: PULL REQUEST Y CODE REVIEW
- Se requiere aprobación de 2 revisores.
- Los revisores deben verificar la lógica de control de acceso.

PASO 5: INTEGRACIÓN Y PRUEBAS EN STAGING
- Se despliega en un entorno idéntico a producción para pruebas de integración.
- Se ejecuta un escaneo de vulnerabilidades automatizado.

PASO 6: APROBACIÓN FINAL Y MERGE
- El Lead Engineer aprueba el paso a producción tras verificar que no existen 
  vulnerabilidades abiertas.

3. MANEJO DE DATOS SENSIBLES
--------------------------------------------------------------------------------
Queda estrictamente prohibido el uso de datos reales de tarjetas o clientes en 
entornos de desarrollo o pruebas. Se deben utilizar técnicas de anonimización 
o datos sintéticos.
